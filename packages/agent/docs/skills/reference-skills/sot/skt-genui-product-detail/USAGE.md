## Read Order

1. `manifest.json`
2. `source/evidence.md`
3. `nodes.md`
4. `component-inventory.md`

## Use For

- Product detail, benefit explanation, selected plan summary, and confirmation-oriented detail screens.

## Do

- Preserve hierarchy between product identity, benefit summary, details, and CTA.
- Capture card/list section rhythm separately.

## Avoid

- Do not turn product detail evidence into generic card-list rules without review.
