## 2026-05-22 - 알아둘 것: type 스키마 혼탁

- 발견: 현재 `WireframeNode.type`이 두 가지 이질적인 개념을 한 필드에 섞어 담고 있음
  - **Leaf 컴포넌트 식별자**: `Button`, `ListText`, `AppBar` 등 카탈로그 entry와 1:1
  - **구조적 노드 식별자**: `page-stack`, `area.static`, `area.dynamic`, `layout-flex`, `layout-grid` — 카탈로그에 없고 렌더 트리의 구조 자체
- 결과: 카탈로그 기반 dispatcher로 전환하려고 보면 type lookup 결과에 세 갈래가 생김 — (1) 카탈로그 hit + 공급 hit, (2) 카탈로그 hit + 공급 miss, (3) 카탈로그 miss(=구조적 노드). (3)을 구분하는 신호가 type 문자열 패턴(`.` 포함, `page-stack` 등)에 묻혀 있어 dispatch에 ad-hoc 분기가 필요해짐
- 영향: "카탈로그는 계약, 패키지는 공급, 렌더러는 중계" 모델로 깔끔히 가려면 구조적 노드를 type이 아닌 다른 축(예: `node.kind` 또는 `node.role: "structural" | "component"`)으로 분리해야 함
- 진행 방향(미정): leaf vs structural 노드 모델링을 분리한 뒤 dispatcher 리팩토링 재개. 본 세션에서는 dispatcher 구현 직전에 정지
- 관련 변경: `database/tables/areas.json` 의 `ogn-mbr-term-list.pattern.id`를 `accordion-list`로 전환(테이블 레이어만 작업), `component-catalog.ts`의 `kind` 필드 주석을 "분기 신호 → 그룹 태그"로 격하
